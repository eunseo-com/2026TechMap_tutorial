# 익명 인수인계 기록 설계

## 목적

Claude와 Codex를 번갈아 사용해도 누구든 GitHub 저장소만 읽고 같은 작업 지점에서 재개할 수 있게 한다. 기록에는 작업자나 도구의 이름을 남기지 않고, 작업 사실·검증 근거·다음 행동만 남긴다.

## 범위

이 설계는 Chapter 1 앱 구현의 범위를 바꾸지 않는다. 협업을 위한 문서와 규칙만 추가한다.

## 구성

### `docs/WORK_LOG.md`

Git으로 추적하는 단일 인수인계 문서다. 문서는 다음 두 부분으로 구성한다.

1. **현재 인수인계** — 현재 작업 상태, 마지막으로 완료한 범위, 마지막 검증, 다음 시작점, 알려진 차단 요소를 짧게 기록한다. 다음 작업자는 이 부분을 먼저 읽는다.
2. **작업 이력** — 최신 항목을 위에 추가하는 표다. 각 항목에는 날짜, 작업 범위, 결과, 검증, 다음 시작점만 쓴다. 작업자 이름, 모델명, AI 도구명은 기록하지 않는다.

기록은 코드·문서·환경처럼 의미 있는 작업 단위가 완료되기 전에 갱신하고, 그 작업의 커밋에 함께 포함한다. 따라서 해당 커밋의 Git 이력과 기록 항목이 같은 변경 단위를 가리킨다. 단순한 탐색·명령 실행·대화만으로는 항목을 추가하지 않는다.

### 공통 작업 규칙

`AGENTS.md`, `CLAUDE.md`, `docs/PROJECT_CONTEXT.md`에 아래 규칙을 추가한다.

- 시작: 원격을 갱신하고 `docs/WORK_LOG.md`의 현재 인수인계를 읽는다.
- 진행: 기존 미추적 파일을 보존하고, 현재 계획의 범위 안에서만 작업한다.
- 종료: 의미 있는 결과를 검증한 뒤 현재 인수인계와 작업 이력을 갱신하고, 결과물과 같은 커밋에 포함한다.
- 커밋과 PR: 제목·본문·트레일러에 Claude, Codex, AI 생성 표시를 넣지 않는다. `Co-Authored-By`를 포함한 자동 저자 표기도 사용하지 않는다. PR은 변경 내용, 검증, 남은 위험만 기술한다.

### PR 템플릿

`.github/pull_request_template.md`는 `요약`, `검증`, `후속 작업 또는 위험` 섹션만 제공한다. 작성자 또는 사용 도구를 밝히는 필드는 넣지 않는다.

## 데이터 흐름

```text
작업 시작
  → git fetch + git status
  → PROJECT_CONTEXT + WORK_LOG 읽기
  → 계획의 다음 미완료 작업 수행
  → 검증
  → WORK_LOG의 현재 인수인계/이력 갱신
  → 일반 커밋 메시지로 결과물과 함께 커밋
  → PR에는 요약·검증·위험만 기록
```

## 초기 기록

초기 `docs/WORK_LOG.md`에는 현재까지 완료된 저장소·협업 환경 구성, 확인된 개발 도구, 그리고 Chapter 1 Task 1이 다음 시작점이라는 사실을 기록한다. 이는 기존 `docs/PROJECT_CONTEXT.md`의 현재 진행 상태와 일치해야 한다.

## 검증 기준

- `docs/WORK_LOG.md`에 현재 인수인계와 초기 이력이 모두 있다.
- 세 공통 문서가 시작·종료 규칙을 동일하게 가리킨다.
- PR 템플릿에 도구·작성자 표기 필드가 없다.
- `git diff --check`가 통과하고, 신규 협업 파일만 의도적으로 스테이징된다.
