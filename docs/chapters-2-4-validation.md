최초 구현은 각 장 7개 단계였다. 이후 초보자 편집에서 준비를 나눠 2장은 9개, 3장은 7개, 4장은 8개 단계가 되었다. 최신 설정 검증과 수정은 [편집 기록](beginner-tutorial-editing.md)을 따른다. 독자는 `ContentView.swift` 하나만 수정한다. 장별 ZIP의 `Starter`에는 준비 코드와 승인된 `Piggy.usdc`를 넣었고, `Answers/1`–`3`에는 단계별 전체 파일을 넣었다. 카메라 설명 키, 실기기 서명, 파일 중복 방지, 모델 누락과 지원 기기 조건은 준비 단계에서 설명한다.

4장에서는 `PatrolSystem.swift`를 읽고 데이터와 동작의 책임을 찾는다. 마지막 비교표는 위치·행동·자산·화면을 이번 예제의 파일과 연결한다. 기존 앱을 한 번에 바꾸라는 결론 대신, 실제 파일 한 개에서 옮길 책임을 적어 보는 단계로 마무리한다.

## 구현에서 지킨 조건

- `SpatialSupport.swift`는 카메라 권한과 기기 지원 여부, AR 세션 상태, 탭 배치를 처리한다. 지원하지 않는 환경에서 검은 화면 대신 필요한 기기를 안내한다.
- 평면에 대한 raycast가 성공한 위치에만 돼지를 놓는다. 다시 탭하면 이전 돼지와 AR 앵커를 교체한다.
- 3장의 가려짐 스위치는 환경 옵션만 갱신한다. 세션과 돼지를 새로 만들지 않아 같은 위치에서 비교할 수 있다.
- 메시 지원 여부를 확인한 뒤 `.mesh`를 요청한다. 메시가 주변 물체를 자동으로 소파나 숨을 장소로 분류한다고 설명하지 않는다.
- 4장은 `ARView`의 비 AR 모드다. `PatrolComponent`가 있는 Entity에만 `PatrolSystem`이 작동하며, 속도를 바꿔도 같은 위치와 진행 방향을 유지한다.
- 본문, 강조된 변경 줄, 복사할 전체 코드, 다운로드는 같은 DocC 리소스를 기준으로 만든다. 렌더러의 이전 코드 비교 상태는 장마다 초기화한다.

## 남은 실제 환경 확인

다음 항목은 아직 실행하지 않았다. 지원 기기에서 직접 확인한 뒤 이 기록을 갱신한다.

- [ ] 2장: 카메라 허용·거절·설정 복귀, 수평면 탐지, 탭 배치와 재배치, 세션 중단 후 복구.
- [ ] 3장: 주변을 스캔한 뒤 메시 수 증가, 물체 뒤에 있는 돼지의 가려짐, 스위치를 바꿔도 위치 유지.
- [ ] 3장: 메시 미지원 기기에서 배치만 제공하고 가려짐 성공으로 오인하지 않는지 확인.
- [ ] 처음 보는 독자에게 설명을 덧붙이지 않고 준비부터 끝까지 진행하도록 관찰. 실제 Xcode 붙여넣기와 막힌 단계·소요 시간을 기록.

예상 30분·30분·25분은 편집상 추정치다. 초보 독자의 완주 시간을 측정한 값이 아니다. 외부 사이트에는 게시하지 않았으며 로컬 결과만 갱신했다.
